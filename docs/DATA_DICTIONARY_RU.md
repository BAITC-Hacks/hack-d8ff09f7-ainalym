Автор: Маулен (соучредитель). Для бухгалтера и закупщика: какой файл что означает, куда он попадает и как читаются спорные ячейки. Источник фактов — `fixtures/PROVENANCE.md`, схема — `src/db/schema.sql`, загрузка — `npm run etl` (`scripts/etl/`). Счётчики — вывод `npm run etl` на 2026-09-23.

Артикулов (`sku`) — 3 909: IEK 3 185, SE 724. Это объединение кодов 1С из всех файлов поставщика; в строках продаж встречаются IEK 2 151 и SE 565 кодов. Коды не выбрасывались, чтобы «попасть» в оценку.

## 2. Ключ

Артикул везде — **код 1С** (`code_1c`, например `130300027_` — сжим У 733M). Артикул поставщика (`article`) и наименование хранятся рядом, но связывают таблицы только по коду 1С. По контракту этот же код идёт в файл для 1С в колонку «Код 1с».

## 3. Как читаются спорные ячейки

| Ячейка | Как читаем | Почему |
|---|---|---|
| Пусто в помесячных продажах | 0 | в отчёте 1С пустая ячейка = не было продаж |
| Пусто в помесячных остатках | «неизвестно» (`opening_qty=0`, `known=0`), **не** ноль | пустой остаток и нулевой остаток — разные факты; расчёт берёт последний *известный* остаток |
| Ноль в остатках | известный ноль (`known=1`) | товара на начало месяца не было |
| Отрицательная строка продаж | сохраняется со знаком | это возврат |
| MOQ / кратность 0 или пусто | 1 | заказ штучный |
| Себестоимость SE = 0 | неизвестна (ненулевая берётся из ячейки точно, до тиын, например 1 050,61) | нулевая себестоимость не бывает; лучше «не задана», чем 0 KZT |
| Себестоимость IEK | неизвестна | в выгрузке её нет |

## 4. Два ряда продаж — не смешиваем

- `qty_file` — число из помесячного отчёта партнёра.
- `qty_lines` — сумма положительных строк «Расходная накладная» за месяц.

За 2024-01 … 2026-09 они расходятся: IEK 6 398 591 против 3 848 302 (×1,66), SE 4 819 965 против 6 841 676 (×0,70). Отчёты сделаны разными выборками (склады, виды документов), поэтому ряды хранятся раздельно, а расчёт показывает, какой он использовал.

## 5. Производные поля

- **Месяц дефицита** (`sales_month.stockout=1`): остаток на начало месяца 0 или неизвестен, а в двух из трёх предыдущих месяцев были продажи; отрицательный известный остаток дефицитом не считается. Таких месяцев — 1 591.
- **Текущий остаток на 22.09.2026** (`sku.on_hand_qty`, `sku.on_hand_as_of`): у SE — «Свободный остаток» из файла товара в пути; у IEK — остаток на начало сентября минус отгрузки сентября по строкам документов. Расчёт берёт его вместо остатка на начало месяца.
- **Медиана месячных продаж** и **95-й перцентиль количества в документе** (`sku.median_month_qty`, `sku.p95_doc_qty`) — для правила разовых заказов.
- **Сезонный индекс поставщика** (`season_index`): выручка 2024–2025 по календарным месяцам, каждый год нормирован, среднее индекса = 1; неполный 2026 год не используется.
- **Категория IEK** — первые 4 символа кода 1С; категория SE — «Категория 2026» (1, 2, 3, 5, 7).
- **Ожидаемая дата прихода товара в пути** = 22.09.2026 + срок поставки (IEK 01.11.2026, SE 11.11.2026) — допущение команды, в файлах даты прихода нет.

## 6. Чего в данных нет

- идентификатора клиента (только номера документов) — поэтому «крупная продажа одному клиенту» ловится на уровне документа;
- цен продажи — поэтому упущенная выручка оценивается только по себестоимости и только для SE;
- сроков поставки и условий оплаты — это политики команды (IEK 40 дн, SE 50 дн, пересмотр 30 дн, предоплата 30 %), они редактируемы.

## 7. Синтетика

`npm run etl` не добавляет ни одной синтетической строки. Синтетические только три пресета ленты для жюри в `fixtures/world_events.jsonl` (разовый заказ, товар в пути +100, изменение цены SE) — они помечены «Симулятор мира — синтетическое событие».
