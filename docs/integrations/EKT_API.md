# ekt.kz catalog API (EKT-1)

- Origin: partner trade-track document; read-only `GET https://ekt.kz/api/products?page=N` and `GET https://ekt.kz/api/products/detail?id=<id>`.
- Auth observed 2026-09-23: HTTP Basic with `EKT_API_USER`/`EKT_API_PASSWORD` returned 200 JSON. Whether credentials are enforced for anonymous requests was not verified. Secrets are read from the process environment only.
- Page 1: `{page:1,per_page:20,count:20,items:[...]}`. Here `count` is **page size**, not catalog total. Page 1 and page 1,500 were populated, so at least 1,500 pages / 30,000 products exist; exact total is not exposed by the page response and remains unverified.
- Page item: `id`, `name`, `article`, `price`, `image`, `url`, `url_api_detail`, `offers`. `offers` was empty on inspected entries. No stock field appears on pages.
- Inspected detail: `id`, `name`, `article`, `description`, `price`, `quantity`, `stores:[{id,name,quantity}]`, `image`, `url`, `offers`, `properties`. `properties` included `CML2_ARTICLE`, `ARTIKULPOSTAVSHCHIKA`, `TORGOVAYA_MARKA`, and `CML2_TRAITS`. Category is derived from the product URL path when absent. No explicit certificate field appeared in the inspected detail; adapter exposes matching property keys if later seen.
- Images and product links are absolute `https://ekt.kz/` URLs. Prices are treated as KZT; the inspected response had no explicit currency key. `quantity` is used for total stock; `stores` for warehouse quantities. `quantity=0` is out of stock, absent quantity is unknown.
- No `RateLimit`, `X-RateLimit`, `Retry-After`, or pagination `Link` headers appeared on inspected responses. `robots.txt` contains generic `Disallow: /*?*`, which also matches parameterized API URLs; the organizer separately supplied these exact API endpoints. No site pages are scraped.
- Client policy: `User-Agent: Ainalym-HackAlem/1.0`, at most 2 requests/s per process, 8 s timeout, one retry on 5xx. Single-SKU live detail uses a 5 s budget and 10 min in-memory cache. Failures fall back to the dated snapshot; missing credentials never produce a live label.
- `npm run ekt:snapshot` walks forward with a 1,500 API request cap, preserves progress and writes a partial snapshot if the cap or an API error is reached. It enriches mapped records with remaining detail budget. `EKT_SNAPSHOT_REQUEST_CAP` can lower the cap for a bounded run.
- `fixtures/ekt_snapshot.json` records product data and `fetched_at`; `fixtures/ekt_map.json` records SKU→product matches and match kind. A null stock means the product has not had a successful detail request. Prices and availability can change after `as_of`.
- Matching order: exact `sku.article` against catalog/supplier article, exact `code_1c` against catalog article, then normalized name with trigram Dice similarity ≥0.9. Mapping is evidence of identity, not a confirmed supplier offer.
- Source labels: `ekt_api_live` → «Каталог ekt.kz · живой API»; `ekt_snapshot` → «Снимок каталога ekt.kz от <дата>».
