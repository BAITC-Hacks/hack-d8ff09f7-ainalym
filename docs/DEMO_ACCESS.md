# Демо-доступ для экспертов

**Форма платформы (вставляет владелец лично):**

- URL демо: `<HTTPS DEMO URL>`
- Код доступа: `<DEMO ACCESS CODE>`
- Ключ для локального live-запуска: `<OWNER-CREATED RESTRICTED PROJECT KEY, ≈ $20 LIMIT>`
- Описание: «Live AI on a synthetic company; server-held keys; offline mode also runs the full scenario locally per README».

Сервер использует только ключи, переданные через окружение при запуске. `OPENAI_API_KEY` — ключ события для демонстрации; `AI_GATEWAY_API_KEY` — ключ Jev владельца. Они остаются на сервере. Отдельный ограниченный ключ для локального live-запуска создаётся владельцем при подаче и вводится им в форму платформы. Не публиковать URL и код в репозитории. Владелец сообщает дату истечения промокредитов при активации.

## Что копировать в README («Демо-доступ»)

> Эксперты открывают публичную ссылку из формы платформы и один раз вводят код доступа. Хостинговое демо работает на обезличенных данных партнёра с живым AI и ключами на сервере; заказы поставщикам остаются черновиками до подтверждения менеджером. Без учётной записи и без ключей можно локально пройти тот же сценарий в режиме `AINALYM_MODE=offline` / `AI_PROVIDER=rules` по инструкции «Установка и запуск». Если лимит живого провайдера исчерпан, интерфейс честно сообщает «Провайдер недоступен»; локальный путь «Правила без LLM» остаётся доступен.

## Эксплуатация

Hetzner: корень запускает `AINALYM_DEPLOY_ENV_FILE=<keychain-built file> scripts/deploy/hetzner.sh <ipv4>` из финального `$REPO_DIR`. Скрипт собирает standalone выпуск в чистом временном каталоге без `.env*`, загружает только приложение и данные, ставит Node 24 + Caddy при необходимости, запускает `node server.js` через systemd и проверяет HTTPS health. На сервере `/etc/ainalym.env` имеет режим 600; SQLite лежит в `/var/lib/ainalym`. Переменные файла: `DEMO_ACCESS_CODE`, `DEMO_DAILY_LIVE_CALLS` (по умолчанию 500), `OPENAI_API_KEY`, `AI_GATEWAY_API_KEY`, при необходимости `TYPESAFE_API_KEY`, `OPENAI_MODEL`, `AI_PROVIDER`. Никаких переменных, клиентов или адресов внешнего учёта в этом окружении нет. Для проверки: `systemctl status ainalym`, `journalctl -u ainalym -n 50 --no-pager`, `curl -fsS https://<host>/api/health`. Повторный запуск того же скрипта обновляет выпуск; при неуспешном health предыдущий выпуск восстанавливается.

Резервный туннель с Mac: передать те же переменные через текущую оболочку, затем `scripts/deploy/tunnel.sh`. Он держит Mac активным, печатает временный HTTPS URL в терминал и не записывает его в репозиторий. Если процесс остановился, повторить команду; новый URL вручную обновить в форме платформы. Данные сохраняются в `DATABASE_PATH`.

Точка интеграции лимита: **каждый** запрос к живому Jev/OpenAI/Realtime провайдеру, включая retry и fallback, идёт через `guardedProviderFetch()` из `src/server/demo_guard.ts` (прямой `fetch` и параметр `fetch` в SDK-клиенте). Она вызывает `reserveLiveCall()` перед отправкой. При исчерпании маршрут возвращает `provider_error`/HTTP 503 с `Provider unavailable` и предлагает типизированный путь «Правила без LLM». UI должен показывать оставшееся число из `/api/health`. Пока адаптеры L3/L5 не подключат эту точку, глобальный лимит не доказан; middleware уже ограничивает входящие API запросы и блокирует AI маршруты после исчерпания счётчика.
